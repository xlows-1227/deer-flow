# HTML 对外发布功能设计

**状态：** 已确认
**日期：** 2026-07-15
**分支：** `codex/publish-generated-html`

## 背景

DeerFlow 目前区分三类文件流转方式：用户自己的文件、对话上传或生成的文件，以及分享给指定注册用户的文件。现有的用户间分享需要登录，并且只允许指定接收人访问。本次需求与其不同：文件所有者需要把对话生成的 HTML 发布为一个稳定链接，让没有 DeerFlow 账号的外部用户也能直接打开。

发布后的 HTML 必须支持交互，但不能作为 DeerFlow 的同源页面直接执行。否则，生成文件中的脚本可能读取应用 Cookie、本地存储或父页面 DOM。

## 目标

- 只允许发布“对话生成”目录中归当前用户所有的 `.html` 或 `.htm` 文件。
- 同一个用户、对话和文件路径只生成一个稳定的永久 URL，直到用户主动取消发布。
- 支持 HTML 中的 JavaScript 和表单交互。
- 让公开内容始终运行在非同源 iframe 中。
- 重复发布保持幂等，并在页面刷新后继续显示复制链接和取消发布操作。
- 源文件被删除或替换后默认拒绝访问。

## 非目标

- 不支持发布用户文件库、对话上传文件或“他人分享”中的文件。
- 不支持包含多个文件的网站包，也不重写 HTML 中的相对资源地址。
- 暂不支持自定义域名、访问统计、访问密码、有效期或搜索引擎收录。
- 不允许发布页面调用需要登录态的 DeerFlow API。

## 架构方案

新增独立的 `file_publications` 持久化模型，不复用面向注册接收人的文件分享表，也不复用对话分享表。一条发布记录保存所有者、来源对话、规范化后的生成文件路径、当前文件系统对象标识、公开 token 和创建时间。通过“所有者、对话、路径”联合唯一约束保证重复发布的幂等性。

所有者调用发布接口时，后端复用现有的对话归属校验和虚拟路径解析逻辑，并额外限制文件扩展名必须是 HTML。如果相同路径已经指向一个新的文件系统对象，用户再次明确点击发布时会更新对象标识，但继续沿用原来的稳定 token。在用户重新发布之前，公开访问会默认拒绝。

外部链接格式为 `/published/{token}`。这个无需登录的 Next.js 页面先获取公开元数据和 HTML 文本，再将文本传给具有以下属性的 iframe：

```html
sandbox="allow-scripts allow-forms"
referrerpolicy="no-referrer"
```

其中刻意不包含 `allow-same-origin`。后端内容接口使用 `text/plain; charset=utf-8` 返回 HTML 源码，并设置 `X-Content-Type-Options: nosniff`；父级预览页再通过 `srcDoc` 注入内容。因此，公开 HTML 可以执行自身交互，但无法继承 DeerFlow 的源。

## 持久化模型

`file_publications` 包含以下字段：

- `id`：UUID 主键，用于已登录所有者的管理操作。
- `public_token`：唯一的高强度随机公开 token。
- `owner_user_id`：指向 `users.id` 的级联删除外键。
- `thread_id`：必填的来源对话 ID。
- `source_path`：规范化后的 `/mnt/user-data/outputs/...` 路径。
- `source_identity`：用户明确发布时对应文件的设备号和 inode 标识。
- `created_at`：包含时区的创建时间。

数据库同时对 `public_token` 和 `(owner_user_id, thread_id, source_path)` 建立唯一约束。取消发布会删除记录，之后公开地址返回 404。源文件被删除或文件对象标识不匹配时也统一返回 404，不暴露具体失效原因。

## API 约定

需要登录的所有者接口：

- `POST /api/file-publications`：接收 `thread_id` 和 `path`，验证所有权与 HTML 类型后创建或返回稳定的发布记录。
- `GET /api/file-publications`：列出当前用户的全部发布记录，让“对话生成”文件列表可以一次映射状态，避免 N+1 请求。
- `DELETE /api/file-publications/{publication_id}`：仅允许所有者取消对应发布。

无需登录的公开接口：

- `GET /api/public-files/{token}`：返回安全元数据，包括 `name` 和 `content_url`。
- `GET /api/public-files/{token}/content`：以不可嗅探的纯文本形式返回 HTML 源码。

创建和列表接口返回 `id`、`name`、`thread_id`、`path`、`public_token`、`public_url` 和 `created_at`。复制链接时，前端使用 `window.location.origin` 组合绝对 URL。

## 前端交互

只有进入“文件 → 对话生成”时，文件页面才加载发布记录。尚未发布的生成 HTML 显示“发布外链”；已经发布的 HTML 显示“复制外链”和“取消发布”。发布和取消操作完成后，使发布记录查询缓存失效，并沿用现有 Toast 模式提示成功或失败。非 HTML 文件、对话上传、用户文件库和他人分享文件均不显示这些操作。

公开预览页包含加载、链接不存在或已停止发布、正常展示三种状态。页面不渲染账号导航或任何需要登录的工作区外壳，并设置 `noindex` 和 `nofollow`，避免搜索引擎收录。

## 异常与安全处理

- 未登录用户调用所有者管理接口时返回 401；跨用户访问对话时表现为对话不存在。
- 非法路径、非输出目录路径和非 HTML 扩展名返回 400。
- 源文件不存在或已被替换时，重复发布和公开读取均返回 404。
- 数据库不可用时，只有已登录的所有者操作返回 503；公开访问仍显示统一错误。
- 不在日志中记录公开 token。
- 公开接口不返回所有者身份、对话标题、内部路径或需要登录的下载地址。

## 验证方案

后端测试覆盖数据库迁移、所有者隔离、路径和文件类型校验、幂等创建、文件替换后的重新发布、无需登录的公开访问、文件删除或替换后的失效，以及取消发布。前端测试覆盖 API 序列化、仅 HTML 显示发布操作、发布和复制及取消状态、公开预览错误状态，以及 iframe 包含交互权限但不包含 `allow-same-origin`。

交付前运行数据库迁移测试、发布路由定向测试、完整前端单元测试、TypeScript 类型检查、ESLint、后端格式和静态检查，并通过浏览器对公开页面进行视觉和交互验证。
