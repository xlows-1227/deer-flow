# 上游 v2.0.0 PR 审计与合并计划

**日期**：2026-07-16
**范围**：上游 `bytedance/deer-flow` v2.0.0（2026-06-25 发布，182 个里程碑 PR）与本仓库 `feat/m1-agent-control-plane` 分支的逐项对比
**目标**：识别上游 v2.0.0 中哪些 PR 已包含在本仓库、哪些可直接合并、哪些需要专项评估，并量化合并收益，指导后续同步工作。

---

## 审计方法

1. 将上游仓库加为 `upstream` 远程并拉取 `v2.0.0` 标签。
2. 分叉点（merge-base）为上游提交 `f9b70713`（PR #3134）。本分支领先 v2.0.0 共 128 个提交，落后 182 个提交。
3. 以 git 祖先关系精确判定每个 changelog PR 的合并提交是否已存在于本分支（而非靠代码相似度猜测）。
4. 对未包含的 PR，统计其改动文件与本仓库自有改动文件（128 个提交）的交集数作为**冲突风险**指标：0 = cherry-pick 基本干净；数值越大越需要手动合并。
5. 抽查确认关键缺失 PR（#3499、#3531、#3654 等）在本仓库代码中无等价实现。

**结论概览**：changelog 收录的 181 个独立 PR 中，**78 个已包含，108 个未包含**（部分提交同时关联两个 PR 号）。

## 合并收益分析

### 性能收益（直接降低时延与资源消耗）

| 收益点 | 来源 PR | 说明 |
|---|---|---|
| Run 查询从 O(n) 降为 O(1) | #3499、#3531 | `RunManager.list_by_thread` / `create_or_reject` / `has_inflight` 与 `MemoryRunEventStore` 目前是 O(内存中全部 run/消息数) 的线性扫描，随网关整体流量增长而退化为热点；建索引后只与单线程深度相关。高并发、长会话场景收益最明显。 |
| ORM 序列化开销下降 | #3654 | `Base.to_dict` 每次调用都执行 SQLAlchemy `inspect()` 反射；按类缓存后消除每个持久化对象序列化时的重复反射成本。 |
| 文件遍历提速 | #3657、#3648 | glob/grep 遍历中 `should_ignore_name` 判断与沙箱路径重写正则编译被缓存/加速，工作区大目录遍历（技能加载、文件工具）时延下降。 |
| 消除事件循环阻塞 | #3311、#3411、#3457、#3505 | 上传扫描、记忆注入（tiktoken 分词）、custom-agent 路由文件 IO、技能压缩包安装这些阻塞操作移出事件循环。当前这些操作会卡住整个网关的所有并发请求，合并后并发吞吐与流式响应的平滑度直接改善。 |

### 稳定性与正确性收益

- **并发安全**：#3413 修复同步单例初始化/reset 的竞态，消除偶发的状态错乱。
- **沙箱可靠性**：#3464（懒加载沙箱状态经 `Command` 持久化，避免重启后状态丢失）、#3518（合并幂等状态更新）、#3494（修复 AIO 沙箱缓存陈旧复用）、#3577、#3623、#3624。
- **流式协议正确性**：#3605（interrupt 正确透传给 LangGraph SDK，客户端可恢复正常的中断/继续交互）、#3631 + #3535（流式与 REST 历史剥离 base64 图片数据，避免超大 payload 拖垮前端与接口）、#3629（中间件 state 保留 sandbox reducer）。
- **数据观测准确**：#3658（token 用量归因到实际使用的模型，多模型混用时成本核算才准确）、#3611（子智能体 span 归属父线程 Langfuse trace，链路完整）。
- **运维能力**：#3706（Alembic 迁移 + 启动时引导建库，schema 升级从手工变为自动化，是多租户/生产化的前置条件）。

### 安全收益

- #3517：仅 aio(DooD) 沙箱模式挂载宿主机 Docker socket，收缩容器逃逸面。
- #3521：默认不再 bind-mount 宿主机 CLI 认证目录，避免凭证泄漏进沙箱。
- #3425：加固 MCP 配置接口对异常输入的处理。
- #3473：无状态 run 接口强制校验 thread 归属，补齐越权访问缺口。

### 用户与渠道体验收益

- 前端修复打包（#3283、#3508、#3519、#3488、#3502、#3649、#3646 等）：消除新会话消息被吞、消息隔离串话、删除会话后状态错乱、长文本溢出、多段消息渲染不全、移动端布局等一批可见缺陷。
- #3534：Telegram 回复改为就地编辑流式输出，IM 渠道体验对齐 Web 端。
- #3591 + #3599：AI 追问建议可关闭，减少无效请求与 token 消耗。

### 与我们自研方向的协同

我们正在推进多租户 Agent 控制面（M1）与 PostgreSQL 持久化。#3706（Alembic）、#3471（auth-disabled 对齐）、#3658（token 归因）与自有工作直接相关，越早合并冲突成本越低；反之越晚合，与我们 128 个自有提交的偏离越大。
